# 0003 · 真钱通道暂不实施，Mock + fail-closed 为当前终态（可重开）

- **状态**：已裁决（2026-11-10，主任授权执行侧裁定）
- **修订**：[0001 先 Mock 再真钱](0001-先-mock-再真钱.md) 的**阶段边界**（0001 的排序与装配闸结论不变，本 ADR 只回答「这一阶段停在哪、什么时候重开」）
- **背景**：`QT-45` ⑤ ① 要求「port 两实现」，但 XTP 侧到今天仍是 **fail-closed 骨架 + 装配闸**；全量适配器受 `docs/x6c-xtp-readiness.md` 的 P1~P5 五项外部条件阻塞（SDK / 测试账号 / 出网 / C 工具链 / 盯盘时间窗），本仓、core、本机、CI 四处均无 SDK。主任把「要不要真钱通道」的决策权下放，要求给出终态而不是继续挂 ⛔。
- **决策**：
  1. **现阶段不投入真钱通道实施**。本仓这一阶段的终态 = **Mock 全链路全绿 + `XTPTrader` fail-closed 骨架（零 fake success）+ 装配闸（缺依赖/无持久幂等键构造期拒绝）**。
  2. **不是「永久不做」**。重开条件 = `x6c-xtp-readiness.md` §4 的 **P1~P5 同时满足**（拿到 XTP SDK、C 工具链、柜台网络可达、测试账号、可盯盘的时间窗）。满足后**另立 X6c 施工单**，并按「真钱形态」另起一条 ADR（低延迟路径是否留在进程内、是否需要独立通道进程）。
  3. `QT-45` 按本裁决**收口为 ✅**：验收口径改写为「Mock 全链路 + 两实现共用同一 `BrokerGateway` 调用面 + XTP 装配闸与 fail-closed 骨架 + DTO 契约测试」；「XTP 全量适配器」不再是本单验收项，转为挂起项 `X6c`。
  4. `X6c` 由 `⛔` 转 **`⏸ 挂起（外部依赖）`**，**不计入开放项**；B 组已落的债务结论（保留期口径 / R8 密钥形状 / R9 暂不收紧）与 C 组接入验收清单**原样保留**，作为重开时的准入清单。
  5. 期间**禁止任何「已支持实盘」的表述**；`api-schema.md` §6 与 `runbook.md` §9 的「永久前置」改写为「**当前阶段前置**，重开条件见本 ADR」。
- **重开流程（写死，避免口头解冻）**：① P1~P5 逐项取证；② 立 X6c 施工单（含全量适配器范围 = 下单/撤单/查单/回报/心跳/重连/限流 + 柜台错误码映射 + 真实 `QuerySettlement`）；③ 立真钱形态 ADR；④ 本 ADR 标 `Superseded by 000N`。
- **代价 / 后果**：
  - 真钱上线无期限推后（有意）；Mock 与柜台的三处已知差异（R9：T+1 / 超卖 / 费用恒零）在重开前不可消除，只能作为 Mock 通过≠实盘通过的残余风险登记。
  - `broker.order_acks` 保留期数值仍是 90 天占位（口径已定，数值待 P2 的柜台可查窗口）；R8 脱敏测试、R9 收紧均随 X6c 重开。
  - 对账的真实柜台侧 `QuerySettlement` 与「对账留痕进 risk」保持未接。
- **否决的替代**：
  - **把 X6c 标 ✅ / 说「两实现已完成」**：骨架不是实现，等于伪造。
  - **写「永久不做」并删除 X6c**：抹掉可重开路径，与主任「不要写成永久不做」的口径冲突。
  - **继续挂 ⛔ 等外部条件**：留下一个永远无法推进的开放项，台账失去判据。

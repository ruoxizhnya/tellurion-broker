# 0001 · 先 Mock 再真钱

- **状态**：已裁决（来源：ADR-D23 / broker-gateway-design.md §3、§4、§6）
- **场景**：实盘通道是整个系统里唯一"错了会真的亏钱"的地方。而它偏偏最难测：柜台有最小单位、涨跌停、T+1、限流、断连、超时后状态未知等一堆行为，且没有沙箱环境能完全复现。
- **决策**：① 先只做 `MockTrader`，把 port、归一化、幂等、超时语义全部跑通；② `XTPTrader` 的**装配前置**是对账方案 + 幂等 + 熔断三项就位，缺一项不允许装配；③ 超时一律返回 `ErrUnknownState`，强制调用方查单，禁止盲目重发。
- **理由**："能不能赚钱"靠策略，能不能"活着"靠通道的正确性。先在没有钱的路径上把所有失败分支跑一遍，是唯一便宜的验证方式；真钱路径只允许承载已经验证过的逻辑。
- **代价 / 后果**：① 真钱上线时间被推后（这是有意的）；② 对账口径要单独设计（订单号 / 成交号 / 资金流水三选一或组合）；③ Mock 与真实柜台的行为差异会带来"Mock 通过但实盘失败"的残余风险，需用回放与小额试跑兜底。
- **替代关系**：无（本仓首条）

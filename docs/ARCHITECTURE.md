# 本仓边界与依赖方向 — tellurion-broker

## 定位

交易通道网关：`XTPTrader` / `MockTrader` = 同一 port 的两个实现。**落地前必须先有对账方案**。

状态：**预留（S0 占位，触发式启动）——尚未启动，无实现**

## 依赖方向（编译器强制）

```
contracts + kit
        ↑
 tellurion-broker  ◀──(下单/回报)──▶  core
```

- 箭头 = import 方向。**不允许反向**，也不允许成环 —— 反向 import 应当**编译失败**，这是判据不是口号。
- 跨仓只认版本号：`tellurion-broker` 以需要的版本出现在下游 `go.mod`。

## 边界表

| | 内容 |
|---|---|
| 允许 | 券商柜台适配（XTP 等）与 Mock 实现；订单/成交回报的可靠投递与幂等；与 core 的对账（日终） |
| 禁止 | 在这里做策略或风控裁决（网关只转发与确认）；import core 的实现包；在没有对账方案的情况下接真钱通道 |

## 关键约束

1. **单仓可构建**：`go build ./...` / `go vet ./...` / `go test ./...` 不依赖任何兄弟目录。
2. **无 `replace`**：指向仓外的 `replace` 一律不接受（CI 会查）。
3. **无 `go.work` 入库**：本地联调可以建，提交即错。
4. **真钱红线**：没有对账 + 幂等 + 熔断之前，本仓只允许 Mock 实现。
